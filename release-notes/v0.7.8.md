<h3 id="cn-v0.7.8">🔌 v0.7.8：修复 SSH 隧道下的工作区选择器</h3>

兼容 DeepSeek Harness `0.2.1-rc.4`；支持范围 `>=0.1.7-rc.1 <0.3.0` 不变。
这一版改了浏览器半边的目录选择逻辑，解决经 SSH 端口转发访问时「选择工作区」直接报错的问题。

- 问题：用 `http://127.0.0.1:<端口>`（SSH 隧道）访问 headless 服务器时，点「选择工作区」弹出 `directoryPicker.pick needs the native capability; the composed picker serves "browse"`；即使不报错，本插件的底部弹层也只能浏览+选择，**不能新建文件夹**。
- 根因一：`directoryFlowDecision` 把 loopback hostname 当作「浏览器就在 dsh 主机上」的证据，选了 `native`。隧道场景下 loopback 只是你本机的回环，服务器根本没有能弹 OS 对话框的显示会话。现在只有桌面壳标记（preload picker、`electron`/`__DSH_NATIVE_HOST__`、`file:`/`app:`/`vscode-webview:` 协议、Electron UA）才算 `native`，其余一律 `browse`。
- 根因二：影子目录流以 `priority: -20` 注册（`single` 槽渲染最低优先级），把官方目录对话框完全遮蔽。本版把它改成 `+20` 让位：官方 browse 对话框驱动主机的 `list`/`createDirectory` 原语，**支持新建文件夹**，桌面和手机都可用。影子注册整套保留——宿主端解析错误时把常量翻回负数即可恢复遮蔽。
- 单测同步；picker 逻辑 16 项全绿，类型检查通过；构建产物确认 `priority: 20`、loopback→`native` 分支已删除；目标实例（SSH 隧道 + 网关）实测「添加工作区 → 新建文件夹」端到端成功。

<h3>升级</h3>

```sh
dsh plugin --profile web add dsh-lan-guard@0.7.8
```
重启 DSH 一次。升级后「选择工作区」在所有客户端（本机、隧道 loopback、局域网手机）统一使用官方目录对话框，可浏览、可新建文件夹。

<h3 id="en-v0.7.8">🔌 v0.7.8: fixes the workspace picker behind SSH tunnels</h3>

Compatible with DeepSeek Harness `0.2.1-rc.4`; the supported range `>=0.1.7-rc.1 <0.3.0` is unchanged.
This release changes the browser half of the directory-picking flow and fixes the hard error that hit every "Select workspace" click behind an SSH port forward.

- The symptom: opening `http://127.0.0.1:<port>` through an SSH tunnel against a headless server made "Select workspace" fail with `directoryPicker.pick needs the native capability; the composed picker serves "browse"` — and even without the error, this plugin's bottom sheet could only list and select, it could never **create a folder**.
- Root cause one: `directoryFlowDecision` treated a loopback hostname as proof the browser sits at the DSH machine and answered `native`. Through a tunnel, loopback is just your own laptop's loopback; the server has no display session for an OS chooser. Now only desktop-shell markers (the preload picker, `electron`/`__DSH_NATIVE_HOST__`, `file:`/`app:`/`vscode-webview:` protocols, Electron UA) count as `native`; everything else is `browse`.
- Root cause two: the shadow flow occupant registered at `priority: -20` (a `single` slot renders the lowest priority) and fully masked DSH's official dialog. It now registers at `+20`, yielding the seat to the official browse dialog, which drives the host's `list`/`createDirectory` primitives, **creates folders**, and works on desktop and phone alike. The shadow machinery stays in place — flip the constant back negative if a host ever mis-resolves remote browsers to `native`.
- Tests updated; all 16 picker-logic cases green, type check passes; the built `lib/client.js` was verified to carry `priority: 20` with the loopback→`native` branch gone; the target deployment (SSH tunnel + LAN gateway) passed an end-to-end "Add workspace → New folder" run.

<h3>Upgrade</h3>

```sh
dsh plugin --profile web add dsh-lan-guard@0.7.8
```
Restart DSH once. After the upgrade every client (local machine, tunnelled loopback, LAN phone) gets the official directory dialog, which can browse and create folders.
